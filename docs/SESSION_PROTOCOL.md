# Operational research session protocol

**Start:** Inspect remote `main` HEAD and any unmerged PR/CI; read `AGENTS.md`, `research/STATE.json`, `research/NEXT_SESSION.md`, all active claim/candidate/novelty/experiment/decision ledgers and last session record. The repository wins over pasted prompts where they differ; log any reconciliation. Work on one named bounded objective; do not pre-execute the next objective.

**Explore:** Define the question and stopping limits. Where computation is helpful, use GitHub Actions as the reproducible compute lab. Each candidate has a frozen experiment spec and contrasting controls; record source, execution and failure information. Independent algebraic derivation and counterexamples precede enthusiasm for attractive plots or digits. Run an immediate source audit for any worthwhile pattern.

**Decision:** Advance, park, refute or continue within a *new* bounded design. State what was learned, what would falsify it, whether evidence is just repeated residue classes, and whether a meaningful theorem is even plausible. Avoid endless low-yield confirmation runs.

**Every fifth substantive session:** perform a progress/correction audit of genuine mathematical increments, novelty competition, compute yield, cost and alternative directions. Stop or pivot a barren line. Complete earlier if consecutive leads collapse under standard facts.

**Close:** Commit session report, exact results/checks/limitations, revisions to ledgers/state, archived former prompt, and next ready-to-paste prompt. Validate local links, Python tests and checker, exact results and GitHub Actions; publish by PR/merge/main when possible. Confirm resulting remote main SHA and PR merged status. A committed prompt is the contract for the next session; a chat-only promise is not sufficient. Report failures transparently and leave no pending unverified claims disguised as complete work.

No journal/preprint/external contact or registry action without specific authorization; none is inherent in research-session approval.
